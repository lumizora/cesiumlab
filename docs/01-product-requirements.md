# cesiumlab 产品需求基线 V1.0

> 文档编号：CL-PRD-001  
> 文档状态：需求基线（供架构设计与 Coding Agent 实施）  
> 日期：2026-11-08  
> 项目版本 V1.0 是**项目首个可交付基线**，不等于 `@cesiumlab/effects` 的 npm 1.0.0。

## 1. 执行摘要

**cesiumlab** 是一项视觉优先的 CesiumJS 研究与开源软件积累计划：用户提供图片、视频、GIF 或视觉构想，AI Coding Agent 从视觉表现出发自主研究、实现并验证 CesiumJS 特效；用户对真实渲染结果做最终视觉验收；适合复用的成熟实现再经过独立封装、工程测试和批准，进入 `packages/` 下的 npm 包。

项目不以 Playground 功能数量、实验数量或发布速度衡量成功，而以三项结果衡量：

1. **视觉成果**：能够产生真实运行、可观察、达到用户预期的 CesiumJS 效果。
2. **可复用资产**：有价值的效果可脱离演示环境，在独立 CesiumJS 项目中使用。
3. **可追溯知识**：每个实验可说明实现原理、技术选择、限制及验证证据。

### 1.1 已确认的产品决策

| 决策 ID | 决策                                                                               | 约束强度 |
| ------- | ---------------------------------------------------------------------------------- | -------- |
| D-01    | 项目名 `cesiumlab`，不限于特效 npm 包                                              | 已确认   |
| D-02    | Monorepo，`packages/effects` 是第一个包方向，未来可以包含其他包                    | 已确认   |
| D-03    | Playground 优先是纯 Web 浏览器应用，不需要 Electron                                | 已确认   |
| D-04    | **视觉参考驱动**，不以现成第三方特效源码作为研发起点                               | 已确认   |
| D-05    | 编码、调试、测试和封装交给 AI Coding Agent                                         | 已确认   |
| D-06    | **先高质量视觉复现，再评估并实施通用化**                                           | 已确认   |
| D-07    | 用户负责最终视觉验收；AI 解释原理、选型和局限，不要求用户编程                      | 已确认   |
| D-08    | Playground 轻量：预览、调参、对照和信息展示；不承担代码编辑、Git 管理和 Agent 对话 | 已确认   |
| D-09    | 公开 Gallery 展示**所有已登记实验**，包含未完成、不可运行及尚未发布的实验          | 已确认   |
| D-10    | npm 包 API 易用优先，并允许有依据的高级扩展和明确的适用限制                        | 已接受   |

> **需求与方案区分**：下面的功能优先级是基于上述决策所做的实施建议，具体框架、工具与内部协议仍由架构文档确定；不得将建议错误表述为用户逐项批准的产品决策。

## 2. 用户、角色与责任

- **项目所有者 / 视觉验收者**：提出视觉目标、观察真实效果、调节参数、给出修改意见、决定是否批准视觉结果、是否进入通用化及是否发布。
- **AI Coding Agent**：负责技术判断、代码、资源、构建、测试、真实视觉检查、缺陷修正、文档和包维护；遇到关键审批边界停止并提交证据。
- **Playground 访客**：浏览各成熟度实验，体验可运行的效果，阅读说明和已知限制；不能将 Prototype 误认成正式 npm API。
- **npm 包消费者**：需要简明 API、可靠生命周期、类型、兼容说明、集成示例与版本记录。

不建设账户、角色后台或云端审批系统；责任划分通过项目规范与外部 Coding Agent 工作流实现。

## 3. 产品边界与信息对象

### 3.1 核心对象

| 对象             | 含义                                       | 边界                               |
| ---------------- | ------------------------------------------ | ---------------------------------- |
| Visual Reference | 用户提供/选定的视觉目标与可观察特征        | 原始第三方素材不默认公开           |
| Experiment       | 对一个或多个视觉目标进行的可运行研究       | 可含专用场景、临时代码，允许不通用 |
| Showcase State   | 实验的推荐模型、相机、时间、参数等展示状态 | 不等于正式效果 API 的默认值        |
| Effect           | 从实验提炼、可独立复用的视觉功能           | 需要清晰的适用对象、生命周期与限制 |
| Package          | 发布多个相关能力的 npm 分发单元            | 必须独立于 Playground 和实验代码   |
| Evidence         | 实际截图/视频、日志、测试记录、版本等      | 概念图不能冒充真实渲染证据         |

允许一个实验包含多个视觉效果、一个效果被多个实验使用，且实验未必会晋升为 npm 模块。

### 3.2 V1.0 非目标

不做 Electron 客户端、低代码搭建、3D 场景编辑器、在线 IDE、内置 AI Coding Agent、任意上传 JS 的远程执行、云账户、多用户协作、自动特效组合平台、复杂任务看板、自动视觉打分、自动 npm 发布或通用 GIS 服务管理。

## 4. V1.0 两个里程碑

**Milestone A — Visual Lab（首个必须完成的闭环）**

- 最小 Web 实验环境，真实 CesiumJS 渲染。
- 至少一个由选定视觉参考驱动的实验，提供默认展示状态、必要参数和视觉参考/说明。
- Coding Agent 给出运行与视觉检查证据；用户决定是否 Visual Approved。
- 公开 Gallery 可展示未完成实验档案，即使没有可运行入口。

**Milestone B — Reusable Library（有合格候选时启动）**

- 从已通过视觉验收、具备复用价值的实验中提炼至少一个候选效果。
- 独立 `packages/effects` 实现，支持包构建、类型及消费端集成测试。
- 验证通用化后视觉不显著退化，形成 npm 发布候选。
- **不强制首个实验必须晋升，也不强制 V1.0 自动发布 npm**；如候选不适合封装，保留实验并另选候选。

## 5. 功能需求清单

优先级定义：**P0** 为 Milestone A 必需；**P1** 为应在实际复用/工程需求出现后纳入；**P2** 为远期候选。部分正式包需求属于 Milestone B 的发布门槛，不能误当作 A 的阻塞条件。

| ID    | 功能需求                             | 优先级             | 验收要点                                                   |
| ----- | ------------------------------------ | ------------------ | ---------------------------------------------------------- |
| FR-01 | Web Playground 运行 CesiumJS 场景    | P0                 | 本地/构建后均可打开，真实 WebGL 渲染                       |
| FR-02 | 实验列表和基本详情                   | P0                 | 所有**已登记**实验档案可见、可链接                         |
| FR-03 | 可运行实验具有 Showcase State        | P0                 | 初次打开能看到目标画面；支持恢复                           |
| FR-04 | 必要视觉参数调节                     | P0（按需）         | 改动能作用于正在运行的效果；无参数时不出现空面板           |
| FR-05 | 视觉参考可查看与对照                 | P0                 | 许可允许时展示，不能公开时显示说明；不以概念图替代运行结果 |
| FR-06 | 原理、选型、限制与已知问题           | P0                 | 非程序员可以理解的简明说明                                 |
| FR-07 | 实验运行状态与成熟度分离             | P0                 | 不可运行/待实现也有档案；不伪装成功                        |
| FR-08 | 现有实验不受新增实验无谓破坏         | P0                 | 构建检查；失败实验可降级为资料页                           |
| FR-09 | 视觉证据、验收状态可追溯             | P0                 | 源码 revision、截图/视频（动态时）、参考版本               |
| FR-10 | 动画暂停/重启、相机重置、截图        | P1，特效需要时前置 | 无法支持时明确禁用，不伪造功能                             |
| FR-11 | 统一 Gallery 分类、搜索、筛选        | P1                 | 实验增多后再扩展                                           |
| FR-12 | 复制观察状态和可分享链接             | P1                 | 可以把参数、相机和 revision 反馈给 Agent                   |
| FR-13 | 构建时自动实验发现                   | P1                 | 元数据与代码分开；不引入未验证入口导致全站构建失败         |
| FR-14 | 多 Showcase、视觉预设、叠加对照      | P2                 | 基于真实需求再立项                                         |
| FR-15 | 高级性能分析、自动视觉对比、视频录制 | P2                 | 专项质量工程，不做首版平台能力                             |

### 5.1 实验登记与公开规则

- **公开全部实验**指公开所有明确登记的实验档案，而不是自动公开仓库中的所有文件、未审查的参考视频或私有数据。
- **成熟度**：Idea / Prototype / Visual Approved / Reusable / Verified / Published 是可增长的结果标签；V1.0 UI 无须实现完整状态机。
- **可运行状态**：Runnable / Unavailable / Not Implemented / Error 与成熟度分开。运行状态须对应检查证据及构建版本。
- Gallery 中不能提供已知会导致全局构建失败的执行入口；不可运行时提供说明及已有安全展示材料。
- 无权公开的参考文件不得进入 public 产物；允许出现“参考素材不公开”的占位说明。

### 5.2 视觉目标与验收

目标优先级：**忠实复现（默认）→ 明确技术限制下的视觉适配 → 仅在用户要求时创意扩展**。

每项视觉实验至少明确：主形态、色彩、光影、动画（如果有）、空间/遮挡关系、已知不确定性。静态图无法证明真实运动轨迹；推断出的动画必须标明为设计选择。

视觉通过条件：

1. 使用真实 CesiumJS 输出，在选定参考、相机和画面比例下进行对比；动态效果使用时间段或关键帧。
2. 显著视觉问题已修正，或连同影响和替代路线明确提交。
3. 当前演示的源码版本、关键参数、资源和相机状态可以追溯。
4. **用户明确确认**，Coding Agent 无权自行授予 Visual Approved。

### 5.3 npm 通用化和发布门槛（Milestone B）

- **Visual Approved** 且确有复用价值才进入候选评估。
- 不依赖 Playground、内部实验文件、隐式全局变量或非公开资源。
- 公共 API 参数类型明确，支持实例生命周期和资源清理；不得承诺无条件通用。
- 在隔离于 Monorepo 路径别名的外部消费项目测试打包结果。
- 提供兼容范围、示例、局限、已知问题以及视觉回归证据。
- 正式 npm 发布需项目所有者批准，版本号与兼容变更另行审查。

## 6. 非功能需求

| ID     | 约束           | 判断方式                                                                      |
| ------ | -------------- | ----------------------------------------------------------------------------- |
| NFR-01 | 真实渲染       | 证据是浏览器/WebGL 输出而非 AI 概念图                                         |
| NFR-02 | 可维护性       | TypeScript、清晰边界、有限抽象；不引入无需求复杂体系                          |
| NFR-03 | 资源清理       | 切换/退出/重复创建时移除自有监听、循环、Cesium 对象；不能复用后调用已销毁对象 |
| NFR-04 | 构建与部署韧性 | 无效实验与公开元数据隔离；发布检查失败不得覆盖可用站点                        |
| NFR-05 | 安全           | 不公开密钥、私有数据；不执行任意访客提供的 JS；第三方资产需授权               |
| NFR-06 | 可访问性与反馈 | 控件标识、键盘操作、加载/失败提示、对比图替代文字                             |
| NFR-07 | 性能审慎       | 首版不设脱离硬件的统一 FPS 承诺；有对比时注明浏览器/硬件/分辨率/测试场景      |
| NFR-08 | 可迁移性       | `packages/` 能在独立 Web 项目消费；Playground 不成为强制运行依赖              |

## 7. 权限与决策边界

| 行为                                           | Agent 权限                                     |
| ---------------------------------------------- | ---------------------------------------------- |
| 研究、试错、创建实验、修复故障、重构未发布实验 | 可自主执行，保留变更记录                       |
| 视觉是否满意、是否开始通用化                   | 必须提交用户决定                               |
| 破坏性公开 API 变更、重大架构迁移              | 先提交方案与影响评估，获得批准后执行           |
| 推送公共包、发布 npm、删除重要历史或敏感数据   | 必须获得明确授权；不得默默执行                 |
| 因工具不足无法检查实际画面                     | 说明“未验证”，提出具体手工验证项；不得声称通过 |

## 8. 关键风险与处理

| 风险                              | 处理策略                                                                   |
| --------------------------------- | -------------------------------------------------------------------------- |
| Agent 没有浏览器或 GPU 能力       | 构建与视觉验收分开；实际未观察的画面不能标记为验证通过                     |
| 参考是静态概念图                  | 明示构图、材质和动画推断；按可观察特征验收                                 |
| 某实验依赖 Cesium 实验性/私有 API | 实验允许探索；在技术说明中标风险，发布前评估替代与版本锁定                 |
| 参考素材或底图版权不明            | 研究原件可内部留存；公开只使用授权资产及明确来源                           |
| 第三方地图/地形依赖网络与令牌     | 默认实验应有不依赖私密令牌的可重复基本场景；外部资源注明服务条款与失败回退 |
| 首个特效不通用                    | Milestone A 仍算成功；Milestone B 改选候选                                 |

## 9. 完成判据和范围管理

**Milestone A 结束**：至少一个真实参考驱动的实验可运行并获得用户视觉验收，网站能展示已登记实验，技术说明与视觉证据可追溯，未完成实验不会无谓破坏其他入口。若技术不可行或尚无视觉参考，应记录障碍，但不得宣称 A 已完成。

**Milestone B 结束**：至少一个独立消费的合格效果模块通过工程检查；是否发布 npm 需独立批准。若尚无可封装候选，B 为“未启动/待候选”，不能伪报完成。

新需求先按“是否直接服务视觉实验与 npm 资产”判断；若非必要，默认入 Backlog。任何提高 P0 范围的修改必须明确说明对应的收益、成本与替代路径。
